# 원문 범위 기반 검색·치환 검증

기준 커밋 `068ee51`의 대소문자 무시 치환은 `İ`의 소문자 확장 뒤 원문 길이와 검색어 길이를 혼동했다. `İAB`를 `i◌̇a`로 찾아 Q로 바꾸면 B가 삭제됐고, `i◌̇AB`를 `İA`로 바꾸면 A가 남았다. 기존 WASM에서 세 사례 × replaceOne/replaceAll/검색 결과 replaceText의 **9건 실패**를 `repro-search-casefold-span.mjs --verify`로 고정했다. ASCII 대조 3건은 통과했다.

검색과 주소형 grep이 원문 Unicode scalar의 `[start,end)`를 공유하도록 두 엔진 파일을 수정했다. 결과 `charOffset`은 start, `length`는 end-start다. 편집 API는 scalar를 받고 문단 모델이 UTF-16 스트림/서식 좌표로 변환하므로 UTF-16 API 계약을 바꾸지 않았다. 본문·셀·중첩 셀·글상자·수식 스크립트의 기존 조회/치환 경로가 같은 범위를 사용한다.

기존 단순 Unicode 소문자 비교 정책을 유지한다. `ẞ`/`ß`는 일치하지만 `ß`/`SS`는 불일치하며, NFC/NFD 정규화를 추가하지 않았다. `İ` 안의 i 또는 결합점에 해당하는 기존 부분 검색도 같은 원문 문자 범위를 반환한다. 정규식·캡처·0폭 매치 API는 현재 grep에 없으므로 지원하거나 검증했다고 주장하지 않는다. `(A)+`, `$1` 등은 문자열로 검사했고 빈 검색어는 무변경이다. 일반 찾기 UI의 지원 범위는 본문과 평면 셀이다. 머리말·각주 검색으로 범위를 확대하지 않았다.

셀 UI의 deferred API는 삭제·삽입 각각 1~8 scalar만 받는다. 소문자 확장 때문에 실제 원문 범위가 8보다 길거나 치환 문자열이 비어 있거나 길면, Bridge가 기존 일반 delete/insert 셀 경로로 보낸다. 일반 경로는 기존 SnapshotCommand 안에서 실행한다. 엔진 deferred API의 무변경 거절 계약은 그대로다.
