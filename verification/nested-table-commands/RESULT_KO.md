# 중첩 표의 잘못된 구조 편집 대상 차단

기준 `d9e28cf`에서 안쪽 표의 병합·분할·행·열 편집 명령이 `cellPath`를 버리고 바깥 표 인덱스를 사용했다. 실제 Mac Chrome에서 여섯 명령 모두 바깥 표 변경을 재현했고, 행 삭제는 안쪽 표와 필드3개까지 제거했다. 이번 후속은 **지원하지 않는 안쪽 표 구조 편집을 무변경 거절**한다. 안쪽 표 저작 기능을 새로 완성한 작업은 아니다.

## 수정 범위

현재 커서와 셀 선택 컨텍스트의 경로 깊이를 EditorContext에 반영해 구조 명령10개의 enabled 상태를 제어한다. 각 execute에서도 두 경로를 검사해 canExecute를 우회한 직접 호출이 root API에 도달하지 않게 했다. root 경로와 flat 셀 축이 일치하지 않아도 거절한다. 일반 셀 텍스트/서식·링크 경로는 변경하지 않았다.

셀 나누기와 줄/칸 추가·삭제 대화상자는 열린 문서 generation·표·셀·선택 범위를 적용 직전에 다시 확인한다. 안쪽 표/다른 셀·범위·문서로 바뀌면 안내를 표시하고 snapshot/저장/참조를 바꾸지 않는다. 생산 Rust 엔진은 변경하지 않았고 기존 `/Users/sw107/Documents/Codex/2026-10-06/task/table-structure-qa/pkg`를 읽기 전용으로 재사용했다. SHA256 `92d6614e5ff0a3ebac84859857086d59ccdbd38d37852e696f3f2bba0f939d4b`. 새 앱/ZIP/target/공개 배포는 없다.

## 제한 및 다음 확인

차단을 검증한 구조는 본문 root2×2 안에 들어간 깊이2/3의 표와 위10명령이다. 전체 안쪽 표 병합·분할/행·열 편집 API, 모든 중첩 깊이, 조상 조판 갱신, 머리말/각주/텍스트 상자 표와 실제 문서 corpus를 지원 완료로 주장하지 않는다. 다음 구현은 깊이/대상을 명시한 엔진 구조 API와 조상 조판·이력·저장 참조를 함께 검증하는 별도 범위가 필요하다.

물리 마우스 hit-test/IME, OS 클립보드, 설치 Electron 호스트 IPC/네이티브 저장 대화상자, 한컴 및 Linux는 미검증이다. 기존 HWP metadata 차이3건과 무편집 HWP→HWPX fill/section 기본값 변환 차이는 이번에 해결하지 않았다. 일반 표 회귀는 이전 단계의 같은 형식 기준 비교를 유지했다. 생산 Rust 변경이 없어 library 전체 unit test는 재실행하지 않았으며 기존 샘플3개 누락 상태를 그대로 남겼다. 샘플 대체/검사 제외는 하지 않았다.
