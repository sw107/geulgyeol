## 최소 합성 사례와 저장 모델 분리

빈 문서에 본문 한 문단, 1행2열 표를 만든다. 왼쪽 셀은 `항목0끝AbC`~`항목123끝AbC`의124개 짧은 문단, 오른쪽은 긴 가로 텍스트1500자와 짧은 문단이다. 본문·셀은 하나의 번호 정의를 공유한다. 표는 RowBreak, 글자처럼 취급하지 않음이다. 머리말·각주·수식·이미지·회전 그룹·중첩 표 없이 재현된다. `scripts/diagnose-vertical-cell-fragments.mjs ENGINE_DIR OUTPUT_DIR`로 생성한다.

124문단을1문단으로 줄인 사례도 포함한다. 방향0/1/2 × 문단1/124 =6문서, 각각 HWP/HWPX12저장물을 Native로 독립 대조했다. 원본 문서는 사용/수정하지 않았다. 상세 입력, 렌더 트리, 페이지 조각 덤프와 로그는 `../vertical-cell-fragment-qa/`에 보존했다.

## 실제 컷과 두 분기의 차이

두 방향의 pagination 덤프는 같은 컷을 갖는다. 배열 첫 값이 왼쪽 셀, 둘째 값이 오른쪽 셀의 유닛 경계다.

| 페이지(0부터) | startCut → endCut | 가로 왼쪽 문단 | 세로 왼쪽 문단 | 조각 높이(px) |
|---|---|---|---|---:|
| 0 | [] → [39,39] | 0~38 | 0~123 | 833.88 |
| 1 | [39,39] → [80,77] | 39~79 | 0~123 | 876.55 |
| 2 | [80,77] → [121,77] | 80~120 | 0~123 | 876.55 |
| 3 | [121,77] → [] | 121~123 | 0~123 | 57.88 |

`table_partial.rs:1098`에서 cut_units를line_ranges로 변환한다. 가로 분기는 문단/줄 범위를 읽고 `start_line>=end_line`인 미선택 문단을 건너뛴다(:1495/:1573). 이전 조각에서 소비한 vpos를 `fragment_vpos_origin`(:1423)으로 보정하고 그 조각의 첫 유효 문단부터 y방향 흐름을 배치한다.

세로 분기(:1311)는 위line_ranges가 이미 있어도 전체cell.paragraphs와 전체composed를 `layout_vertical_cell_text`에 전달하고continue한다. 이 함수에는 페이지 컷/선택한 문단·문자 범위/이전 조각 소비량 입력이 없다. 매 호출에서 전체 모델을 조각의 **높이**로 다시compose(:121~130), 글자열을 오른쪽→왼쪽으로 새로 배치(:270/:534), y원점도 현재조각상단으로 새로 시작한다. `char_y+advance`가 조각 하단을 넘으면break(:563)하여 일부 글자가 방출되지 않는다.

clip 누락도 아니다. 네 조각 모두 `clip=true, page_fragment=true`이며 SVG는 `svg.rs:678`에서 실제 셀bbox clip-path를 적용한다. 방향1의 앞 세 조각은 각각912개, 마지막은555개 TextRun bbox가 셀 밖에 완전히 놓인다. 방향2의 마지막은444개다. 이 글자를SVG에 방출했다고 화면에 보인다고 할 수 없다.

## 범위만 제한하는 안이 충분하지 않은 이유

가로 유닛은 세로 y방향의 줄 높이·간격 원장이다(`cell_units_uncached`, table_layout.rs:8946). 이 합성 모델의 각 저장 줄은 line_height1000, line_spacing600, segment_width19956HU이다. 세로 렌더링에서는 line_height+line_spacing이 **열의 x피치**21.333px로 바뀌고, segment_width는 `calc_vertical_cell_content_height`(:4132)에서 **열의 y길이**처럼 읽힌다. 게다가 unit 구성의세로 분기는inner_width를compose예산으로 쓰지만 실제세로그리기는inner_height를쓴다. 측정·페이지컷·그리기가 같은 축/소비 단위를 공유하지 않는다.

line_ranges를 그대로 적용해 첫 조각에39문단만 넘겨도 한 문단한열로 약824px(39×21.333에서마지막열간격8제외)가 필요하다. 둘째/셋째41문단은약866.7px가 필요하다. 셀전체폭은279.69px이며 내부폭은더작다. 중복이1회로 줄어도 clip으로 많은 문단이 사라진다. 마지막3문단도 높이57.88px에서 세로 글자 배치/줄 재구성이 달라진다. 단순 Vec슬라이스는 `cp_idx`까지0부터 다시 매겨 실제문단39가문단0의편집경로로기록되는 추가 위험이 있다.

따라서 **line_ranges 전달이나 반복문 skip만으로 124문단 각 1회·누락 0을 보장하는 안은 채택하지 않는다.** 요청된 안전한 최소 수정 조건을 넘으므로 이번에는 엔진을 수정하지 않았다.

## 가장 좁은 다음 설계안

첫 범위는 **합성 문서의 단순 텍스트와 1행 표 안의 세로 셀**로 한정한다. 저장 HWP의 특수 vpos, 병합·중첩 표, 이미지·수식, 글상자, 세로 번호 표시는 동시에 확장하지 않는다.

1. 전체 셀의 열과 글자 배치를 페이지 조각과 독립적으로 한 번 계획한다. 각 단위에 원본 문단 인덱스, 문자 구간, 열 인덱스, x/y 범위를 보존한다. 폭과 높이의 예산을 명시하고 가로 CellUnit 높이를 열 범위로 재사용하지 않는다.
2. 페이지 계획이 이 단위의 소유권을 배분한다. 한 열이 페이지 경계를 넘으면 문자 구간을 상보적으로 나눈다. 열 너비가 셀 폭을 넘을 때 어느 새 조각으로 넘길지도 먼저 정한다. 셀·행 높이 측정과 pagination이 함께 알아야 하는 정책이다.
3. table_partial은 계획된 원본 문단·문자 범위와 조각 좌표 변환을 전달한다. 세로 그리기는 전체 셀을 다시 compose하거나 소비한 문자를 다시 내보내지 않는다. 셀 clip은 최후 경계로 유지하고 편집 경로의 문단과 char_start는 원본 값을 유지한다.
4. 합격 조건은 각 모델 문자의 소유권 1회·누락 0, 문단 완전성, clip 안의 bbox, 방향 1/2와 회전, 번호 ID·수준·직접 서식 참조, undo/redo·HWP/HWPX 재열기, 가로 셀 회귀다. 완전한 문자열 횟수만 검사하지 않는다.

이 설계에는 페이지 컷과 세로 조판의 공동 계약 수정이 필요하다. 이번 진단에서는 구현하지 않았다. 단일 짧은 문단을 후속 조각에서 건너뛰는 패치는 가능해 보이지만, 124문단 문제를 해결하지 않으므로 이번 목표의 수정으로 제시하지 않는다.
