# 대형 문서 Enter/undo

본문·셀의 일반 Enter에서 다음 문단 스타일을 적용하면서 정확한 문서 스냅샷으로 undo하는 경로를 측정했다. 새 next-style planner 자체는 기존 split과 비슷했지만, 문서 스냅샷 복원 시 전체 문단 높이를 재측정해 undo 시간이 대략 두 배가 되는 회귀를 확인했다.

전체 Document 스냅샷을 그대로 보존하고, 지원하는 단순 문서에서는 문단 구성 결과와 문단 높이 측정값도 저장하도록 보완했다. undo/redo는 저장한 문단 높이를 재사용하고 표는 다시 측정한다. 페이지네이션과 페이지 트리 무효화, 스타일·문서 참조 복원, 원자적 실패 처리, 스냅샷 해제 규칙은 유지한다. 새 typed WASM/Bridge API는 본문·셀 일반 Enter에서만 선택적으로 사용한다. 기존 snapshot API와 머리말·각주 등 다른 명령의 기본 경로는 유지한다.

캐시는 건당 추정 16MiB, 저장소 합계 추정 32MiB로 제한한다. 제한을 넘으면 오래된 선택 캐시만 제거하며 문서 스냅샷·ID는 보존한다. 내장 폰트, exact-font shaping context, 복잡한 shaping/그림 투영·정규화, 번호·각주, 완료되지 않은 배치/dirty 상태, 불일치한 파생 데이터에서는 기존 복원을 쓴다. DPI 또는 한글2024 호환 모드가 달라져도 기존 복원을 쓴다. 이 숫자는 캐시 payload의 추정치이며 전체 메모리/RSS 상한이 아니다. 기존 최대 100개의 전체 문서 스냅샷 예산도 바꾸지 않았다.

## 측정 결과

| 위치 | 본문 문단 수 | Enter 이전→수정 (ms) | undo 이전→수정 (ms) | undo 감소 |
|---|---:|---:|---:|---:|
| 본문 | 32 | 1.45→1.43 | 3.05→1.47 | 51.9% |
| 본문 | 512 | 24.30→24.66 | 49.52→25.20 | 49.1% |
| 본문 | 8,192 | 497.94→504.00 | 926.82→506.43 | 45.4% |
| 셀 | 32 | 1.42→1.38 | 2.93→1.41 | 51.9% |
| 셀 | 512 | 24.66→24.94 | 50.14→25.20 | 49.7% |
| 셀 | 8,192 | 504.59→506.77 | 924.06→507.87 | 45.0% |


각 입력·모드에 예열 3회와 측정 12회, 교대 실행 순서와 시도 사이 GC를 적용했다. 기준은 dev.5의 실제 WASM, 수정 후는 새 release WASM과 현재 Studio 명령을 사용했다. 파싱과 SVG·재열기 검사는 Enter/undo 타이머에서 제외했다. 표의 수치는 원시 12회 측정의 통상적인 중앙값이며 p95와 원시 자료는 proof.json 및 저장소 밖 QA 자료에 있다.

셀 입력의 32/512/8192는 **본문 문단 수**이며 표 자체는 1×1로 고정되어 있다. 큰 표·많은 셀의 성능을 측정한 결과가 아니다. 큰 입력은 약 71만 Unicode scalar의 한글·ASCII 합성 문서다. 기존 전체 페이지네이션에 따른 대형 문서 Enter 지연은 남아 있다. snapshot 복사와 planner보다 페이지네이션이 다음 조사 대상이다.

## 검증

- 선택 캐시: 본문·셀 × 32/512문단, 전체 Document와 모든 페이지 SVG를 세 차례 undo/redo에서 비교(24회), HWP/HWPX 재열기 8건. DPI·호환 모드·배치·내장 폰트 플래그·각주 fallback, 12개 스냅샷의 캐시 제거와 ID 보존, 32,768문단의 건별 상한 초과 복원, 잘못된 ID의 무변경 실패를 확인했다.
- next-style native: 162사례, undo/redo 288회, HWP/HWPX 재열기 324건, merge 역연산 36건, 원자적 거절 126건.
- 실제 generated WASM/현재 UI 명령: 288사례, 실제 UI 명령 72건, undo/redo 576회와 모든 페이지 SVG 일치, merge 역연산 72건, 원자적 거절 21건. 저장 결과 1,224건의 모든 지원 문단 텍스트·스타일·문단 모양·글자 모양 run과 스타일 참조를 native 기준과 비교했다.
- 기존 스타일 전파(48), 스타일 삭제(16), 셀 수식(72), 회전 그룹 해제(108), 스타일 메타데이터(8), 이벤트·타원 동작 검사는 모두 통과했다.
- native 라이브러리/예제 및 wasm32 라이브러리 Clippy `-D warnings`, 전체 Studio tsc와 Vite, UI 명령 mock 11건을 통과했다. Desktop 관련 30 pass/0 fail/1 skip/1 TODO. 변경 없는 localhost 서버 검사는 이번 실행에서 제외했다. skip은 비공개 layout 입력, TODO는 createEmpty 기본 DocInfo 문제다.
- 큰 문서의 최종 화면 상태와 재열기 검사: 본문·셀 각각 8,192문단/400페이지, undo/redo 전체 페이지 SVG의 SHA-256 일치와 모든 본문·활성 셀 스타일 ID 보존. 두 형식 재열기 12건. 타이밍 뒤 별도 검증 프로세스로 실행했고 Node 192MiB 힙, RSS 768MiB/WASM 512MiB 제한을 유지했다.

## 범위와 다음 확인

실제 Mac 화면에서의 편집, 한글 IME, GUI 저장 대화상자, 한컴에서의 재열기는 검증하지 않았다. Electron의 Node 모드로 실제 WASM과 UI 명령을 실행했으며 GUI 성공으로 해석하면 안 된다. Linux 실기 실행도 하지 않았다. exact-font shaping 등 복잡한 문서에서의 최적화 효과는 입증하지 않았고 기존 복원을 사용한다.

기존 dev.3/dev.5 앱, 공개 beta.2·beta.1, 기본 앱과 원본 문서를 변경하지 않았다. 이번 최적화는 소스·WASM·Studio 빌드 후보이며 dev.5 앱 안의 엔진을 교체하거나 새 앱/ZIP/릴리스를 만들지 않았다. 다음 단계는 별도 버전의 Mac 개발 앱으로 패키징하고 실제 GUI/IME, 폰트가 등록된 문서, 큰 표·중첩 셀에서 반복 Enter/undo 메모리를 확인하는 것이다.
