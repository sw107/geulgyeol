# 표의 실제 프레임 하단 진단

검토 기준 소스는 `8512984d0d1d41d16484784937b8c6f1a891af39`, PR 6 병합 main은 `2ce682f1a23f52ebae359d7cb82eeef9aa00c443`이다. `dev/table-painted-height`의 별도 후속 수정이며 기존 검토 SHA와 이전 QA를 보존했다.

## 원인과 수정

앞간격 수정 뒤 남았던 Table 4.0px 진단을 동일한 실제 Electron 저장 파일로 재현했다. 표의 실제 하단은 985.3600px, 본문 하단은 985.0933px다. 흐름은 이미 표와 바깥 아래 여백 283HU(3.7733px)를 소비해 989.1333px에 있었다. 페이지 레이어 표 경로는 표 함수의 반환값을 사용하지 않고 그 흐름 위치를 콘텐츠 하단으로 기록했다. 표 함수 역시 흐름 커서를 되돌리지 않는 반환 계약을 갖는다. 따라서 이 사례의 4.04px는 실제 테두리 0.2667px와 아래 여백 3.7733px가 합쳐진 진단 회계 차이다. 앞선 여백·반복 머리행 수정이나 과거 redo 결함을 새 결함으로 분류하지 않았다.

캡션이 없는 Page/Top·0 세로 오프셋·RowBreak·자리 차지·겹침 불허 표로서 별도 후행 본문을 이미 emit한 경우, 페이지 레이어로 이동하기 전 해당 최상위 표 노드의 실제 프레임 하단을 콘텐츠 경계로 기록한다. 흐름 커서·배치·페이지 수·직렬화는 그대로 둔다. 다른 앵커 계약과 캡션은 기존 경로를 유지한다. 경고를 끄거나 2px 기준을 늘리지 않았다.

## 검증

- 보존한 수정 전 Native에서 회귀 스크립트의 첫 원본 사례가 4.0px 경고로 실패한다. 수정 후 같은 실제 저장 파일의 SVG·문서 모델이 일치한다.
- 새 WASM과 Native로 API 파생 경계 파일 16개를 검사했다. HWP/HWPX 각각 아래 여백 0·900·-150HU 및 비대칭 위/아래 여백을 포함한다. 실제 테두리 초과 0.2667·1.2667px는 경고가 없고 2.2667·3.2667px는 네 사례 모두 경고가 남는다. 겹침 허용으로 대상에서 제외한 두 사례는 기존 Table 28.0px와 `LAYOUT_OVERFLOW type=PartialParagraph` 65.4px 경고를 유지한다. 판단 기준은 정확한 SVG 테두리 좌표와 원본 쪽 여백이며 반올림된 API 좌표로 대체하지 않는다.
- 기존 실제 Electron 저장 파일 264개를 최종 Native로 재검사했다. 전체 SVG·페이지 수·본문·셀 내용·문단/문자 서식·표 속성·쪽 여백이 일치하며 기존 12개 Table 경고는 0개가 됐다.
- 최종 새 엔진의 Mac Electron 44.3.0: 16개 편집 사례, undo/redo 32쌍, 실제 호스트 IPC를 통한 양형식 저장·재열기 32건. 긴 표의 첫·중간·끝 편집 대상은 0·7·14쪽이고 표 뒤 본문은 15쪽이다. 짧은 표의 첫·중간·끝 셀과 후행 본문도 검사했다. 반복 머리행·모든 셀과 본문 텍스트 소유권·서식·쪽 정의·전체 SVG·정확한 이력 복원이 보존됐다.
- 그림 기하 52회/468쪽: 최대 테두리 초과 +0.2667px, 실제 글자 하단은 본문 안쪽 0.6133px, 숨김 0·부분 잘림 0. 제품의 deferred pagination 완료 뒤 비교했다. 렌더러 오류 0, 정상 종료 코드 0.
- 그 32개 실제 저장 파일도 Native에서 전체 모델·SVG 일치, Table/DRAW/CELL 경고 0. 따라서 기존 264 + 새 32 + API 경계 16 = 312개 Native 파일 비교다. API 파생 경계 사례를 실제 앱 편집 건수로 세지 않는다.
- 새 WASM SHA256은 `4af551769fa8d5d0eb27fda4f4e208e04eb72cb6ea18ab13562038659cb4fcd0`이며 Electron이 받은 바이트와 일치한다. 오프라인 Native/WASM 빌드, Node 구문 검사, `git diff --check` 통과. 최종 빌드는 target 4.48GiB 이하·가용 공간 15GiB 이상을 유지했다.

## 재실행과 한계

먼저 기존 `check-electron-table-host-spacing.mjs`로 실제 저장 manifest를 만든다. 새 회귀는 `node scripts/check-native-table-painted-height.mjs <새 QA 경로> <WASM pkg> <Native horizontal_table_saved_check> <실제 저장 manifest>`로 실행한다. 출발 사례는 manifest의 `whole-none-fit-hwpx-input-1.hwp`다. 새 출력 경로를 요구하며 기존 파일을 덮어쓰지 않는다. 전체 raw 증거는 저장소 밖 `../table-painted-height-qa/`에 보존하고 공개 소스에는 해시와 요약만 넣었다. 중간 실패·체크포인트·원본·기존 앱·beta.2도 보존했다.

일반 in-body 표·캡션·다단·특수 컨트롤·다른 float 계약 전체에 무해하다고 인증하지 않는다. 기존 샘플 세 개 누락 때문에 전체 Rust lib 테스트는 실행 가능한 상태가 아니며 Native 예제와 실제 앱 검증으로 범위를 명시했다. Linux·물리 IME·OS 파일 선택창·수동 GUI·한컴 앱 비교·새 앱 패키징은 하지 않았다.

누적 표 수정은 다음 Mac 베타의 소스 후보로 검토할 근거가 늘었지만, 실제 부분 저장 프레임과 병합 셀의 조각 경계 검증이 남아 있다. 그 검증과 독립 코드 검토 후 별도 후보 앱의 저장·종료·복구 회귀를 거쳐 패키징 적합성을 확정해야 한다. 버전 변경·공개 릴리스는 없고 공개 베타는 beta.2다. 다음 구현/검증 우선순위는 실제 부분 저장 프레임 및 병합 셀의 첫·중간·끝 조각 편집이다. 원본 앵커 순서를 바꾸는 splitParagraph 조건도 별도 재현 후보로 유지한다.
