# Mac 업데이트 사용성 검토 — 2026-10-06

사용자는 유료 공증이나 공식 배포보다 반복 업데이트의 번거로움을 줄이길 원한다. 이번 변경은 다음 패키징에 사용할 안내 개선과 기존 패키지 식별자 점검이다. 앱을 새로 만들거나 설치/업데이트를 실행하지 않았다. 인증서·계정·공증·원격 릴리스도 변경하지 않았다.

## 현재 확인한 일관성

현재 beta1 소스의 Mac 패키징 명령과 최소 재포장 스크립트는 같은 앱 이름 `GeulgyeolBetaNext`, bundle identifier `org.geulgyeol.beta.next`를 사용한다. 기존 beta1 앱의 main/helper Info.plist와 실행 파일 이름도 이 구성에 일치한다. desktop/main.cjs는 `GeulgyeolBetaNext` userData 폴더와 single-instance lock을 사용한다. 같은 베타 계열에서 이름/ID/설정 위치를 버전마다 바꾸지 않는 구성이다. 별도의 기존 beta.2 설정 폴더를 유지한다.

사용자 안내는 최초 `~/Applications` 설치 또는 기존 설치 위치 유지, 문서 저장·앱 종료, 이전 앱/ZIP 백업, 새 `.app` 패키지 전체 교체, 실제 표시 버전 확인, Dock의 오래된 사본 정리, 문서 사본 재열기와 되돌리기 순서로 개선했다. 설정 폴더나 문서를 지우는 단계는 없다. 설치 경로를 유지하면 여러 사본을 혼동할 가능성을 줄이지만, 새 다운로드의 보안 경고 제거를 보장하지 않는다.

## 다음 패키징에서 유지할 검사

- 동일 베타 계열의 앱 이름·bundle identifier·설정 폴더 및 main/helper 실행 파일 이름을 일치시킨다. 버전은 package.json, 번들 정보, 화면·도움말에서 일치시킨다.
- 최신 개발 커밋의 새 WASM/편집 UI를 빌드하고 네이티브 검증과 별도로 패키지 안의 실제 엔진/API를 실행해 확인한다. 현재 repackage-mac-candidate.py는 검증된 dev4 엔진 SHA와 beta1 버전에 고정된 전용 스크립트다. 이번 메타데이터 수정이 이미 들어 있는 새 패키지라고 해석할 수 없다.
- 모든 리소스·ASAR 및 header integrity를 확정한 다음 전체 번들을 서명하고 `codesign --verify --deep --strict`로 확인한다. 마지막 파일 변경 뒤 서명 검사를 마친 앱으로 ZIP을 만든다. 현재의 ad-hoc 서명은 Developer ID 서명/Apple 공증과 구분한다.
- ZIP CRC/전개 파일 일치/SHA256, 공개 첨부를 만들 때의 다운로드 바이트·해시 일치를 확인하고 명시한 소스 커밋과 엔진 SHA를 기록한다. 원본·기존 개발 후보·기존 공개 ZIP은 보존한다.
- 기본 프로세스 실행·정상 종료와 실제 GUI·물리 IME·다운로드 실행의 결과를 각각 기록한다. 기존 beta1의 자동 검사 결과를 새로운 패키지의 결과로 재사용하지 않는다.

## 범위

빠른 시작 문서의 로컬 개발본만 수정했다. 기존 공개 릴리스 첨부는 유지한다. 이 안내의 Finder 교체·Dock 정리·새 버전 경고 발생 여부는 이번 환경에서 실제 GUI로 실행하지 않았다. 이름/설치 위치 일관성은 업데이트 사용성과 식별의 문제이며 보안 예외를 대신하지 않는다. quarantine 삭제, Gatekeeper 비활성화, 예외 자동 승인이나 경고를 피하기 위한 업데이트 경로는 만들지 않는다. 유료 가입·인증서 발급·공증 제출 요청도 없다.
