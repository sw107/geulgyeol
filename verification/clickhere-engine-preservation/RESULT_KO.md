# 일반 본문 누름틀의 서식·각주 보존 수정

기존 `bd4e95b`의 UI Unicode scalar 수정 위에 엔진 보존 수정을 구현했다. 동일 검증 스크립트로 기존 pkg의 혼합 서식/각주 위치 손실 두 건을 다시 재현하고, 별도 WASM 후보에서 두 건의 보존을 확인했다. 전체 누름틀 기능 완료나 실제 GUI 성공을 뜻하지 않는다.

## 수정

- Unicode scalar 문단 인덱스, UTF-16 저장 좌표, 8-unit 제어 토큰을 분리한다. 누름틀 안내·값의 공개 스트림 좌표도 astral 문자의 UTF-16 폭을 반영한다.
- FIELD_END를 별도 controls[] 소유자로 세지 않는다. 편집 전 비필드 컨트롤 위치를 확보하고 삽입/값 교체/제거/본문 및 공유 셀 입력 후 새 텍스트 위치로 옮긴다. 각주 참조가 앞 누름틀 위치로 이동하던 원인을 수정했다.
- 저장 좌표를 재구성할 때 char_shapes·range_tags·line_segs 경계를 함께 이동한다. 제어 간격이 줄어들어도 경계가 이전 글자 안으로 넘어가지 않게 해 반복 undo/redo의 앞 글자 서식 누출도 막았다.
- 완전한 UTF-16/제어 토큰 축으로 설명할 수 없는 문단에는 새 누름틀 삽입을 변경 전에 거절한다. 불명 제어·짝 없는 필드·내부 슬롯·orphan/title 표식을 지원한다고 확대하지 않는다. 본문 raw_stream 무효화도 삽입 성공 뒤에 한다.

기존 pkg에서도 같은 현재 스크립트의 기본 모드가 두 실패를 재현한다. 후보 모드는 `CLICKHERE_EXPECT_PRESERVED=1`이며 보존을 강하게 비교한다. 실패 조건이나 원본 fixture를 대체하지 않았다. 실제 렌더/DOM/플랫폼 입력은 adapter이므로 GUI/물리 IME 인증과 구분한다.

## 후보·자원·한계

후보는 `../clickhere-engine-qa/pkg`에만 있다. SHA-256 `f0abe21a6227a522c9137987f73b8dcadc863445d53cc00bdeb6f015ac087af8`. 기존 pkg SHA-256 `015e64b941e60f85fb10a86810aaef0909cd4a0f8de3992246b49c13d2a262c7` 및 기존 앱4개 ASAR는 그대로다. 앱 통합·교체·패키징·공개 푸시/릴리스는 진행하지 않았다.

승인된 이번 단계 target 상한4GiB에서 관측 최고 약3.226GiB, 최종 약3.036GiB다. Native 최고 증가 약195MiB, 최종 WASM 빌드 최고 증가 약85MiB로 추정 상한300/500MiB 안이었다. 관측 여유 공간은10GiB 이상을 유지했고 캐시 삭제/새 clone은 없었다. 각 빌드의 명령·최고치·종료 코드는 [proof](proof.json)에 있다.

`cargo test --lib field_query::tests`는 기존 include_bytes! 원본3개가 없어 컴파일되지 않는다: `3-09월_교육_통합_2022.hwp`, `hwp3-sample16-hwp5.hwp`, `hwpx/aift.hwpx`. 파일 복원·대체·검사 제외로 우회하지 않았다. Native 예제 검증을 library unit test 통과로 표시하지 않는다.

실제 Mac GUI·물리 IME·Linux·새 앱 패키징은 미검증이다. 중첩 필드/필드 병합·복잡한 제어 소유권의 전 범위 인증은 남아 있다. 긴 세로 셀 pagination/metric adapter도 기존 미지원·보류 상태다. 다음은 별도 앱 후보에 이 엔진을 연결한 실제 Mac 입력/선택/누름틀 이동/undo·redo·저장 재열기 확인이다.

재현 예제: `engine/examples/clickhere_preservation_check.rs`. 전체 자동 증거·저장 산출물·빌드 로그·체크포인트는 `../clickhere-engine-qa`에 보존했다.
