# Mac 자동 저장과 인쇄 상태 복원 경합

실제 idle 자동 저장으로 별도의 결함 두 개를 재현했다. 인쇄 준비 중 자동 저장이 그때의 “인쇄 준비 중… (2/2)”를 복원 대상으로 기억하면, 인쇄가 끝난 뒤에도 자동 저장의 1.6초 타이머가 끝난 인쇄 진행률을 다시 표시했다. 실제 IndexedDB transaction은 commit됐지만 oncomplete callback을 늦춘 상태에서 양식 모드로 전환하면, 늦은 저장 완료 표시와 타이머가 새 모드 메시지를 덮어썼다. PR47의 메시지 소유권 검사와 달리 실제 자동 저장 스케줄·commit·복원 타이머를 사용한 새 경합이다.

상태 표시만 수정했다. 자동 저장 표시를 `AutosaveStatusDisplay`로 분리해 기존 `PrintStatus` 소유권을 재사용한다. 진행 중 임시 메시지도 정상 복원 대상을 공유하므로 자동 저장이 인쇄 진행률을 정상 상태로 기억하지 않는다. 다른 작업이 상태를 바꾸면 늦은 완료·타이머 복원을 중단한다. 이전 타이머가 늦게 전달돼도 새 세션을 완료 처리하지 않는다. 남아 있는 인쇄 실패 메시지와 성공 재시도의 복원 정보를 백그라운드 알림이 소비하지 않도록 보존한다. 완료/실패 표시의 기존 1.6초/4초 시간은 유지했다.

`AutosaveManager`와 `autosave-store`는 변경하지 않았다. 복구 스케줄·export·transaction·dirty·사용자 저장·draft 정리 경로도 수정하지 않았다. main은 PR47 병합 `f6334b4d3e8e13c15b1b845e805bec3384367a0b`를 반영했으며 그 뒤 소스와 테스트를 검사했다. PR47 고정 head `53dbfc85eca65ad856b354d4ab4cb5703759b657`, 검증 파일 11개, runtime 53개를 보존했다.

baseline HWP에서 두 결함을 확인했고, 수정 후 설치된 Mac Electron 44.3.0의 HWP/HWPX 합성 2페이지에서 두 경합만 좁게 다시 검사했다. 자기 QA 프로필의 idle 시간을 2초로 설정해 실제 관리자가 저장하도록 했으며, 사용자 설정은 바꾸지 않았다. 첫 검사에서는 실제 복구 commit 뒤 인쇄를 끝내고 타이머가 정상 메시지로 복원하는 것을 확인했다. 두 번째는 commit 후 보류한 oncomplete callback을 실제 양식 모드 명령 뒤 전달해 완료 통지와 타이머가 “양식 모드”를 보존하는 것을 확인했다. 실제 manager callback과 읽기 전용 IndexedDB 조회로 commit 바이트를 확인했으며, 저장 성공 이벤트를 가짜로 주입하지 않았다.

두 경합 전후 HWP/HWPX export 전체 바이트·본문·모든 화면/인쇄 SVG, 파일명/dirty와 undo/redo stack 길이를 비교했다. A/B 편집 후 undo하여 dirty=true·undo 1개·redo 1개인 상태였고, 실제 redo/undo도 실행했다. 각 문서의 복구 HWP 바이트는 현재 export 바이트와 같았다. 별도로 넣은 무관한 합성 draft의 바이트는 바뀌지 않았다. 마지막 실제 사용자 저장은 호스트 IPC와 파일시스템으로 해당 형식의 전체 바이트를 영속화했고, dirty=false가 된 뒤 현재 문서의 복구본만 제거됐다. 무관한 draft와 이력은 유지됐다. 양식 모드 및 사용자 저장으로 의도한 모드·파일명·clean 변경은 이 비교에서 구분했다.

기존 PrintStatus 9개를 재사용하고 observer adapter도 공통 테스트 지원 파일로 옮겨 중복 코드를 피했다. 추가 7개는 자동 저장과 인쇄의 복원 대상 공유, 늦은 저장 통지, 취소된 이전 복원 타이머의 새 세션 중 전달, 새 인쇄 중 자동 저장 타이머, 동일 문자열 외부 쓰기, 인쇄 오류 복원 정보, 실패/보호 표시 시간이다. Node 검사는 DOM record와 타이머 adapter이며, 실제 DOM/자동 저장/transaction 동작은 native 검사에서 확인했다. PR47의 기존 native 18개 경로를 다시 실행했다고 주장하지 않는다.

전체 desktop 74개 중 73개 통과·기존 complex-picture fixture 부재 1개 생략. 별도 소유권 검사 16개 통과, TypeScript noEmit 통과. 명령·exit·stdout/stderr 해시와 원본 TAP을 보존했다. 소스 전후 manifest 75개와 별도의 실제 runtime 전후 manifest는 동일하다. `proof.json`에 baseline/수정 native 결과를 합쳐 불필요한 QA 문서 복제를 줄였고 원본 native 증거와 실행 소스의 해시도 기록했다.

baseline과 수정 앱은 강제 종료 없이 exit 0으로 종료했다. OS window.print 호출은 차단됐고 시도 0회였다. 파일 선택 결과는 합성 경로로 제어했으나 실제 IPC/파일 저장 경로를 사용했다. 전체 앱 패키징·엔진 빌드·외부 설치는 하지 않았고 자산 13개를 재사용·변경된 3개만 기록했다. 기존 dirty 4개·잠금파일 3개·WASM·이전 증거 273개·컴파일 캐시 133개를 보존했다. 정상 증거 771207168바이트·실패 증거 124387328바이트, 미완료 phase 없음. 전체 소유 경로 4717756416바이트로 7GiB 안에 있다.

OS 인쇄·독립 PDF 끝 검색·Linux는 미검증으로 유지한다. 취소된 이전 인쇄 rAF를 새 인쇄 중 전달하는 조합도 아직 미검증이다. 자동 저장의 취소된 복원 타이머 검사는 별도 unit 범위다. 다음 검증 후보는 아직 완료되지 않은 복구 commit과 실제 사용자 저장을 동시에 수행하는 경우다.
