# 각주·미주 선택 없는 다음 입력 글자 서식

기준 `0185924102f63d8f5795ab68cd828407669beef1`에서 굵게 예약 후 실제 onInput을 호출하면 각주/미주 네 사례 모두 보통 글자를 삽입했다. 이 누락을 구현했다. 기존 스타일 전파·삭제 참조 보존, 중첩 문단, 선택 글자/문단 서식 기능은 회귀 검사로 보존했다.

| 항목 | 결과 |
|---|---|
| 캐럿의 굵게·기울임·크기·글꼴·장평/자간 | 새 입력에만 적용. 예약 시 문서/정의/이력 무변경 |
| 연속 입력·예약값 조회·토글 | 입력 후 앵커 연장, 미확정 값을 조회하여 반복 토글/증감 반영 |
| 이동·선택·편집 영역·문서 교체 | note 주소·커서 revision·문서 세대로 만료. 이동 후 돌아와도 되살아나지 않음 |
| 조합 갱신·취소·완료 | 시작 스냅샷으로 재작성/취소. 완료된 글자와 서식은 기존 snapshot 이력 한 건 |
| undo/redo·Enter·삭제·병합 | note 문맥 및 문서/서식/정의/렌더 복원. 끝에서 Delete는 redo 보존 |
| 비지원 속성·참조 | 기존 엔진 validator로 무변경 거절. 이미 있는 예약과 redo 보존 |
| HWP/HWPX | 재열기 전체 SVG 136/136 일치. Native에서도 번호·자동번호/본문 참조·스타일 보존 |
| 실제 GUI·물리 IME·Linux·새 앱 패키징 | 미검증. 자동 WASM/UI 입력 검사와 웹 빌드만 수행 |

본문·셀의 기존 예약 모델과 이력 API는 변경하지 않았다. 노트도 실제 이동 시 만료하고 그 자리에서 이어지는 입력은 앵커를 연장한다. 노트의 별도 revision은 이동→복귀와 선택→해제를 구분한다. 기존 body 예약은 임시 note 모드에서 숨긴 뒤 body 위치가 유지되면 재사용하는 현재 정책을 그대로 유지했다.

개체/필드 문단은 기존 note 글자 범위 API의 거절 경계를 유지한다. 머리말/꼬리말의 선택 없는 예약 서식은 이번 범위에 포함하지 않았다. 기존 한컴 원본 문서에 대한 직접 GUI 편집/호환성 성공을 주장하지 않는다.

다음 확인: Mac 실물 GUI에서 툴바/대화상자 표시와 단위, 실제 한글 IME/유령 입력·포커스 전환, 큰 문서 snapshot 메모리/반응성, 앱에 반영한 뒤 저장 재열기. Linux는 같은 엔진의 부가 실행 확인이 남아 있다.
