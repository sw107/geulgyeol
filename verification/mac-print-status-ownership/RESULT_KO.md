# Mac 인쇄 재시도 상태 메시지와 경합 보존

인쇄 실패 뒤 성공한 재시도가 시작할 때 이전 실패 문구를 원래 상태로 저장해, 성공 후에도 오류를 다시 표시했다. 준비 중 다른 작업의 최신 메시지 역시 다음 진행률 갱신이나 finally 복원으로 덮어썼다. PR46 고정 SHA `1e190a09875e3ef4aca30a42957ebd2b799f08a2`의 실제 Mac 앱에서 실패→성공 및 실제 `view:form-mode` 작업의 메시지 덮어쓰기를 재현했다.

인쇄 상태만 다루는 `PrintStatus`를 추가했다. 자신이 표시한 실패는 그 전에 있던 정상 메시지를 기억하므로, 성공한 재시도에서는 그 메시지로 돌아간다. 다른 작업이 상태 요소에 쓰면 인쇄는 이후 진행률·오류·완료 복원을 중단한다. 실제 DOM MutationObserver와 `takeRecords()`로 아직 callback이 실행되지 않은 같은-turn 쓰기 및 동일 문자열의 외부 쓰기도 구분한다. 오류 문자열 prefix를 지우는 방식이 아니므로 다른 작업이 다시 쓴 동일 오류도 보존한다. PDF 안내 취소 전에는 인쇄 상태 세션을 만들지 않아 이전 실패 표시와 복원 정보를 유지한다. 관찰은 정상 완료 시 해제하고, 실패가 남으면 다른 쓰기나 다음 재시도까지만 유지한다.

PR46 병합 main `618794939ad0415c7c1ef83d078b31465224149f`를 fast-forward로 반영했다. 이 반영은 실제 native 검사에 사용한 인쇄 소스를 바꾸지 않았고, 별도 소스 hash 대조 후 전체 테스트와 타입 검사를 다시 실행했다. PR46 head·공개 검증 파일 11개·private runtime 53개는 고정 보존했다.

설치된 Mac Electron 44.3.0과 합성 2페이지 HWP/HWPX에서 각각 다음 9가지를 검증했다.

- 인쇄 실패→PDF 안내 취소→성공: 실패는 취소 중 유지되고 성공 후 원래 정상 메시지로 복원.
- PDF 준비 실패→인쇄 미리보기 성공: 이전 PDF 오류 대신 원래 정상 메시지 복원.
- 첫 페이지 렌더 뒤 더 최신 메시지를 쓴 경우: 뒤쪽 진행률·완료가 보존.
- 준비 중 실제 양식 모드 명령: 모드가 실제로 바뀌고 “양식 모드” 메시지가 보존. 이후 실제 명령으로 기본 편집 모드를 복원.
- 다른 작업이 진행률과 동일한 문자열을 다시 쓴 경우: 외부 소유로 보존.
- 최신 메시지를 쓴 뒤 두 번째 페이지 렌더 실패: 새 오류가 그 메시지를 덮어쓰지 않음.
- 실패와 재시도 사이에 다른 메시지가 발생한 경우: 최신 메시지 보존.
- 실패 문구와 동일한 문자열을 다른 작업이 재기록한 경우: 외부 메시지를 오래된 인쇄 오류로 오인해 제거하지 않음.
- readiness frame 완료를 강제로 늦추고 최신 메시지와 중복 인쇄 요청을 넣은 경우: 준비 중 알림, 단일 자식 창, 늦은 완료 뒤 최신 메시지 보존.

각 경로 후 실제 HWP/HWPX export 전체 바이트 SHA256, 본문, 모든 화면·인쇄 SVG SHA256, 파일명·dirty, undo/redo stack 길이를 비교했다. 성공 미리보기의 전체 SVG 노드·속성·텍스트도 비교했다. A/B 편집 후 undo 상태여서 undo 1개·redo 1개, dirty=true였으며 마지막에 retained redo와 undo를 실제 실행해 원래 편집 바이트로 돌아왔다. 양식 모드 작업으로 의도한 모드 변경 외 문서와 이력은 그대로다.

최종 `npm test --prefix desktop`: 67개 중 66개 통과·기존 complex-picture fixture 부재 1개 생략. `node --test desktop/tests/print-status.test.cjs`: 9개 통과. `node node_modules/typescript/bin/tsc --noEmit`: 통과. 모두 exit 0이다. Node 검사는 DOM mutation record adapter로 같은-turn/동일문자열·연속 실패·요소별 격리·observer 정리를 검사했고, 실제 DOM MutationObserver 동작은 별도 native 양형식 검사로 확인했다.

원본 TAP, 명령·exit·stdout/stderr 해시와 별도 전후 소스 69개 manifest, 실제 runtime 전후 manifest를 함께 기록했다. 모두 검사 전후 동일하며 `proof.json`은 실행한 helper·runner·Electron·WASM·native 증거의 해시와 한계를 담는다. baseline은 HWP 8개, 수정 native는 양형식 각각 9개다. 강제 늦은 완료/중복 요청은 수정 버전에서 추가 검사했으며 baseline에서 별도 재현했다고 주장하지 않는다. baseline 실행 소스와 최종 실행 소스도 각 phase에 해시 고정했다.

baseline과 수정 QA 앱 모두 강제 종료 없이 exit 0으로 종료했다. 자기 QA 앱에서 window.print 호출을 차단했고 호출 시도는 0회다. 실제 OS 인쇄 다이얼로그·물리 출력·독립 PDF 끝 검색·Linux는 미검증이다. native 파일 선택은 합성 fixture로 제어했다. 전체 앱 패키징과 엔진 빌드는 하지 않았고 수정 번들은 13개 자산 재사용·3개만 변경 기록했다. PR46의 이전 검증 자료를 수정하지 않았다.

기존 dirty 4개·잠금파일 3개·WASM·이전 증거 273개·컴파일 캐시 133개를 보존했다. QA 정상 증거 727662592바이트·실패 증거 158240768바이트, 미완료 phase 없음. 전체 소유 경로 4708065280바이트로 7GiB 이내다. 다른 기능의 상태 복원 정책은 변경하지 않았다. 다음 검증 후보는 복구용 자동 저장의 지연된 상태 복원과 인쇄 메시지의 경합이다.
