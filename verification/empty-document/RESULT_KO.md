# 빈 문서 HWPX 재출력 결함 검증

대상은 b41551c 이후 로컬 개발 소스다. `createEmpty()`가 DocInfo 서식 정의 없이 ID 0을 내보내던 결함을 팩터리에서 수정했다. 첫 저장은 암묵적 0을 사용했고, 재열기는 명시적 charPrIDRef 0을 만들기 때문에 두 번째 HWPX 저장이 미등록 ID 검사에 걸렸다. 기존 실패 샘플과 로그는 host-save-qa에 보존했다.

수정은 7언어 기본 글꼴, 10pt 글자 모양, 160% 문단 모양, 탭 정의, 바탕 스타일, 구역 수 및 기본 탭 간격 8000의 초기화다. 첫 문단에 구역/단 정의를 넣지 않아 초기 편집 좌표를 유지했다. 가져온 문서, Document::default(), 파서와 직렬화 검증은 변경하지 않았다. 원래 실패 샘플의 미등록 ID 0 및 합성 ID 42는 재출력이 계속 거절되며 문서 모델이 그대로다.

실제 UI의 새 문서는 WasmBridge.createNewDocument → createBlankDocument → bundled blank2010.hwp를 사용한다. 이 경로에는 필요한 DocInfo가 이미 있어서 이번 미등록 ID 0 오류가 없었다. 보존 dev12 앱의 실제 새 문서 버튼/SDK 초기화로 이를 확인했다. 제품 UI 변경은 없다.

## 완료 검사

- bare/내장 템플릿 각각 공백·첫 `첫 한글🙂𐐀 입력`·14pt/굵게/기울임/가운데/180% 서식: WASM 6상태, 36개 저장 파일, 60회 HWP/HWPX 3회 저장 사슬 재열기. Native 동일 6상태/60회. 각 첫 형식에서 두 번째 형식 두 가지와 세 번째 재저장을 모두 검사했다. Unicode API로 원문 입력을 확인했고 TEXT API의 CP949 수치 참조 계약은 유지했다.
- 현재 엔진의 Mac Electron 렌더러: 실제 새 문서 버튼, CDP 문자 입력, 실제 굵게 명령, 두 형식 6개 저장 및 18회 재열기/재저장. 동일 ABI glue를 확인하고 비동기 WASM 로드로 현재 모듈을 시험 주입했다. 앱 파일·ASAR·서명·보안 설정은 수정하지 않았다.
- 현재 WASM 36개 + 실제 UI 현재 엔진 6개 + 기존 UI 6개 + 실제 저장 처리 결과 11개 = 59개를 최종 Native 바이너리로 독립 재열기. 같은 저장 바이트를 읽은 전체 SVG가 모두 일치하고, Native 두 형식 재저장·재열기 118회 완료. 캐시 복원 후 QA에 보관한 Native 바이너리로 같은 59/118 검사를 다시 통과했다.
- HWPX 30개에서 실제 header 정의와 참조 2,086개 일치. hh:paraHead의 상속 글꼴 sentinel 4294967295 210개를 별도 집계했다. 일반 문단/스타일의 미등록 참조는 허용하지 않았다.
- 저장 동작 회귀 19개 검사 묶음, 실제 저장 완료·취소·실패 후 재시도·중복 방지·temp 충돌을 포함한 정식 테스트 18개 모두 통과. 기존 bare 표 저장 TODO를 실제 통과 검사로 전환했다. 스타일 삭제/전파의 기본 회귀도 포함했다.
- Native standalone example 단위 검사 1개, TypeScript noEmit, Clippy `--lib --example empty_document_check -- -D warnings` 최종 코드에서 통과했다.

## 남은 차이와 검증 범위

내장 템플릿에는 이번 수정 전에도 있던 투명 채우기 조회값 차이가 남았다. HWP의 `solid/#999999/-1`이 HWPX에서 `none/#000000/0`으로 조회된다(fillType/patternColor/patternType, 글자·문단). 검사기는 22스타일의 기존 템플릿에서 이 세 값의 정확한 조합만 별도로 기록한다. bare 문서의 값은 정확히 일치한다. 이를 전 서식 보존 성공으로 주장하지 않는다. WASM 사슬에서 42개, 실제 현재 UI 사슬에서 30개 scope 차이를 기록했고 원시 결과는 QA에 보존했다.

UI의 저장 전 SVG와 저장 후 재열기 SVG는 기존 앱/현재 엔진 모두 6파일에서 원문 문자열이 달랐다(공백 예: 저장 후 구역 정의와 body clip/group 추가). 비교를 정규화하지 않았다. Native/WASM 전체 SVG 일치는 동일 바이트를 다시 읽은 상태의 59파일에 대한 결과다.

현재 앱 패키지를 새로 빌드하지 않았다. 실제 창을 쓴 엔진 시험 주입 검사이며, 현재 엔진을 포함한 서명 앱의 일반 실행/파일 열기 통합 검증은 다음 확인 항목이다. 물리 IME·OS 클립보드·OS 저장 대화상자는 검사하지 않았고 사용자 파일/권한/클립보드를 변경하지 않았다. Linux 실행 환경이 없어 별도 Linux 검사는 하지 않았다. 전체 Rust lib 단위 검사는 기존에 없던 fixture 3개가 필요하므로 이번 standalone example 검사로 대신했으며 전체 성공으로 주장하지 않는다.

## 보존 및 산출물

검증 루트: `../empty-document-qa`. `pkg/`, `native/empty_document_check`, 최종 입력/저장 샘플·manifest·원시 로그·실패 시도·보호 해시·예산 기록을 보관했다. 새 target/App/ZIP/공개 푸시/릴리스는 만들지 않았다.

기존 캐시 512개를 APFS clone으로 백업하고 변경된 11개를 복원했다. 보호 대상 37,826파일의 해시 변경·누락 0. dev12 strict ad-hoc 서명 유효, 소유한 모든 검증 창 정상 종료(exit 0). 마지막 예산과 실제 사용량은 proof.json의 protection/budgets에서 확인할 수 있다. target 4.5GiB 이하, 실제 free 15GiB 이상을 전 실행에서 지켰다. 기본 앱·사용자 문서·기존 dev 후보와 beta.2를 보존했다.

다음은 내장 템플릿의 투명 채우기 의미/잔여 payload 보존 문제를 별도 해결하고, 공간 예산 안에서 승인된 단일 후보 패키지의 실제 파일 열기·저장 통합 검사를 진행하는 것이다.
