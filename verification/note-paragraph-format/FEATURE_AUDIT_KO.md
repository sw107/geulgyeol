# 각주·미주 문단 서식 및 다음 입력 서식 대조

2026-10-06, 기준 `8ede89e`에서 두 편집 흐름을 실제 WASM과 현재 UI 메서드로 확인했다.

| 흐름 | 수정 전 확인 | 이번 판단 |
|---|---|---|
| 캐럿의 문단 정렬·줄간격·들여쓰기 | 각주/미주 × ASCII/Unicode, 12사례에서 해당 문단을 정상 변경 | 기존 setter/캐럿 경로 유지. 최종 실제 명령 라우터에서도 12대조군의 변경·undo/redo를 확인 |
| 문단 모양 대화상자 | 12요청 모두 명령0, HWPX·전체SVG 무변경. 조회는 각주 문단이지만 적용은 본문 범위 형식이며 대상 산출이 빈 배열을 반환 | 실제 누락으로 선정 |
| 여러 각주 문단 선택 후 정렬 | 4입력 모두 끝 문단 하나만 변경 | 같은 선택 문단 서식 기능의 대상 오류로 수정 |
| 선택 없이 굵게 → 실제 입력 | 4입력에서 예약 서식 없음. 실제 `onInput`의 note 삽입은 진행되나 새 글자는 굵게가 되지 않음 | 비지원 재현만 기록. 이번 구현에서 제외 |

선택한 기능 한 가지는 **각주·미주의 선택 문단 서식과 문단 모양 대화상자의 정확한 대상 연결**이다. 정렬·줄간격·들여쓰기/여백을 각 선택 문단 자체 모양을 기반으로 적용한다. 선택이 없는 대화상자도 열 때의 정확한 note 문단을 저장한다. 조회는 정렬된 선택의 첫 문단을 사용하며 적용은 같은 범위를 사용한다. 본문의 기존 포함식 문단 범위와 같이 끝 문단도 포함한다.

선택 없는 다음 입력 글자 서식은 현재 body 좌표의 예약 앵커, 비조합 note 입력, 조합/직접 입력 및 IME 이력을 함께 다뤄야 한다. 이번에는 이를 정상 지원으로 주장하거나 별도 입력 설계를 확장하지 않았다. 실제 GUI 도구가 없어 화면/물리 IME 반복 시도는 하지 않았다.
