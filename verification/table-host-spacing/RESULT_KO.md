# 표 뒤 본문의 한 페이지 배치와 문단 간격

검토 기준 35f2bf48137b0a99e1957717de322dcee8c122f7은 변경하지 않았다. 별도 dev/table-host-spacing에서 후속 수정을 만들었으며 PR 기준 main은 d7e2222538b7731c0d6a90225d6c4bb49bd09b50이다.

## 재현과 변경

줄 정보가 없는(NoLS) 앵커 문단의 앞간격 24px, 본문 줄 높이 13.3px, 마지막 표 조각 뒤 남은 공간 17.69px인 사례를 실제 Mac Electron에서 재현했다. 기준 엔진은 앞간격을 fit에서 빠뜨렸으며 글자 하단이 본문 경계를 29.64px 넘었다. 기준 실행은 초기 배치 재현이며 편집·저장 검증 0건이다. 수정 후 표의 마지막 페이지는 14, 본문 시작은 15다. 한 페이지 표의 별도 사례에서도 남은 공간 20.83px에 앞간격과 본문 줄이 들어가지 않아 표 페이지 0, 본문 시작 1을 확인했다.

앞선 continuation 배치와 동일한 소스 조건(단일 단·표 각주 없음·단일 RowBreak 표·본문 텍스트 앞의 앵커·글자처럼 취급하지 않음·Page/Top/offset=0·TopAndBottom·겹침 불허)을 whole-table fit 경로에도 적용한다. 표 테두리와 바깥 아래 여백 뒤에 별도 본문 항목을 배치한다. 문단 앞·뒤간격과 줄 간격은 본문이 소유하며 이중 소비하지 않는다. NoLS 문단의 일반 flow 정책이 앞간격을 0으로 만드는 경우에도 이 후행 본문은 실제 resolved style의 앞간격을 fit 예산에 포함한다. 페이지 상단에서는 저장 첫 줄 위치에 따른 기존 앞간격 규칙을 fit과 paint가 같은 도우미로 계산한다.

앞간격 10px·뒤간격 5px의 표를 편집해 본문이 새 쪽으로 이동하면 다음 문단의 낡은 저장 위치가 뒤간격 5px를 다시 줄이는 사례도 실제 Electron에서 발견했다. 별도 후행 본문이 소비한 흐름 높이를 즉시 뒤따르는 문단의 하한으로 유지한다. 원본 저장 위치나 문단 속성은 변경하지 않는다. whole-table 경로는 기존 표 배치기의 하단 기록을 유지하며 별도 후행 흐름 값으로 다시 덮어쓰지 않는다. 진단 기준을 완화하거나 숨기지 않는다.

긴 NoLS 본문은 표시 시 45자 임시 줄바꿈, 편집 시 실제 본문 폭을 사용하여 편집 후 3쪽이 HWPX 재열기 후 4쪽이 됐다. 최종 구현은 단일 단의 해당 NoLS 후행 본문에서 구역/단 정의·표 외 다른 본문 컨트롤이 없을 때, 원본을 복제한 파생 조판만 편집과 같은 ParagraphBox::body_for_style 및 reflow 계산을 사용한다. 원본 줄 정보는 계속 비워 둔다. HWPX의 합성 줄 캐시 생략 정책도 유지한다. 동일 폭·글꼴 조판이 줄바꿈과 기준선을 함께 결정하므로 임의 위치 보정을 넣지 않는다. 최초 NoLS 본문 입력은 기존의 제한된 SnapshotCommand를 사용해 undo가 원본의 줄 정보 부재도 복원하도록 한다. 두 번의 undo/redo와 양형식 재열기에서 전체 SVG가 일치하고 긴 본문은 3쪽으로 유지된다.

배치 근거는 이전 결과 문서의 소스 앵커·텍스트 순서와 자리 차지 규칙을 따른다. 실제 한컴 앱과의 교차 배치 검증은 수행하지 않았다. 문자열·용지/표 위치 속성·기존 문자 스타일 ID를 옮기거나 clip으로 본문을 감추지 않는다.

## 검증 범위

새 사례는 한 페이지 표, 앞간격 10px의 한 페이지/긴 표, 앞간격 24px·뒤간격 10px의 NoLS 짧은/긴 본문, whole/continuation의 terminal fit 부족이다. 양형식 14개 입력에서 첫·중간·끝 셀 입력, 본문 입력, 단일 치환, 크기 무변경을 검사하고 세 종류에는 높이 증가·감소도 적용한다. NoLS 원본 8개에서 Native 모델의 host line segments=0을 직접 확인했다. 긴 원본 본문은 4235 스칼라다. 테스트의 declaredBeforePx/declaredAfterPx는 resolved 물리 간격이며 API의 원시 속성 표시값과 구분한다.

실제 Mac Electron 44.3.0에서 신규 96개 사례, undo/redo 164쌍, 호스트 HWP/HWPX 저장·재열기 164회를 검증했다. 동일 엔진으로 기존 56개 사례·100쌍·100회도 재실행했다. 합계 152개 사례·264쌍·264회다. 동일한 실제 저장 바이트 264개를 Native에서 전체 SVG·페이지 수·본문/셀 문단 속성·문자 스타일 ID·표/용지 속성으로 독립 비교했다. 정확한 실행 수치·해시·정상 종료와 진단 수는 동반 proof.json에 기록한다.

신규 가시 배치 검사는 260회·1270페이지, 기존 회귀는 160회·1226페이지다. 신규 최대 테두리 초과는 0.27px, 글자 하단은 본문 안 0.61px이며 기존 수직 기하 허용치 2px 이내다. 수직 clip으로 숨겨진 글자와 1px 이상 잘린 글자는 0이다. 셀 문자열을 실제 조각 순서대로 모아 비교하고, 반복 머리행은 각 표 페이지의 전체 문자열로 비교한다. 본문·후행 문단과 모든 가시 비공백 스칼라의 소유권을 검사했다. 첫 NoLS 본문 편집에는 스냅샷 자원 하나만 추가되는지 확인했다. deferred pagination은 제품의 idle 경계를 기다린다.

겹침 허용·문단 기준·양수 offset·앵커 앞 표시 텍스트의 양형식 8건은 이전 엔진과 전체 SVG가 같다. 적용 조건 양형식 2건에서는 SVG가 달라지는 차등 감도도 확인했다. Node 문법, 생성 바인딩을 사용하는 TypeScript, git diff --check를 검사했다. 파일 선택 응답과 전용 프로필은 QA에서 제어했고 실제 키보드·제품 대화상자·history·호스트 저장 IPC·재열기를 사용했다.

첫 시도의 NoLS 기준선 차이, 긴 NoLS 본문 3→4쪽 차이, 뒤간격 회귀 및 표 내부 높이의 4px 진단의 중간 증거는 모두 보존한다. 하단 기록 덮어쓰기 제거 뒤 기존 264개 저장 파일의 전체 SVG가 그대로임을 비교했으나 Native Table 진단 4px가 12건 남았다. 같은 저장 파일 1건은 보존한 35f 기준 엔진에서 Table 28px와 본문 65.4px 진단을 냈다. 새 엔진의 본문/그림/셀 draw 진단은 0이며, 내부 Table 반환 높이와 최종 가시 테두리의 차이는 잔여 과제다. 진단을 끄거나 허용치를 늘리지 않았다. 최종 실제 앱 묶음도 다시 실행해 통과했고, final-3·regression-2 및 해당 Native 증거를 기록했다. 이전 안쪽 여백 문서에서 첫 거절은 전체 모델·양형식 export SHA·history·dirty 불변을 직접 검사했으며, 반복 거절은 history·dirty 불변을 직접 검사했다는 구분도 유지한다.

## 보존·재실행·한계

원시 증거는 ../table-host-spacing-qa에 보존한다. scripts/check-electron-table-host-spacing.mjs의 인수는 전용 QA 실행 디렉터리와 WASM 바인딩 디렉터리이며 GEULGYEOL_HOST_SEEDS로 seed JSON을 지정한다. 기본 seed JSON 위치도 해당 QA 디렉터리다. seed는 앞선 합성 48행 API QA 문서를 바탕으로 짧은 셀, 반복 머리행, 후행 본문, 원본의 NoLS 부재 및 실제 문단 간격/아래 여백을 구성한 로컬 자료다. 재실행에는 이 seed와 기존 Electron QA bootstrap/runtime, 설치된 Electron 및 UI 의존성이 필요하다. 양형식 원본·개인 파일·저장 파일·프로필·폰트·WASM·대용량 캐시는 커밋하지 않는다.

최종 WASM SHA는 a456c8841c6595102c499bceaeacf7955d4fa207c9e95d02882059070dce5ac8이며 두 실제 Electron 실행이 받은 바이트 SHA도 같다.

기존 Electron·오프라인 Rust·기존 UI 자산을 재사용했다. 기존 build 산출물은 체크포인트로 보존하고 target 4.48GiB, 가용 공간 최소 15GiB를 감시했다. 한 감시 실행은 빌드 중 임시 파일 소멸로 du가 종료했으며 완료된 Native 빌드 로그를 보존하고 측정기를 보완했다. 최종 빌드의 완료·용량 증거를 별도로 기록한다. 영구 삭제·보안 설정 변경·설치·중복 앱 패키징·병합·릴리스는 하지 않는다.

수직 SVG 기하·clip 검증이며 raster 픽셀, 물리 IME, OS 파일 선택창, 수동 GUI, Linux와 한컴 교차 검증은 아니다. 합쳐진/중첩 셀, 실제 부분 저장 프레임, 각주, 다단 및 첫 문단이 아닌 host의 독립 사례는 아직 검증하지 않았다. 기존 Rust lib 전체 테스트의 누락 fixture 차단점은 재실행하지 않았으며 Native example과 실제 Electron으로 검증했다. 모든 문서의 overflow 해결을 주장하지 않는다.

다음 우선 후보는 위 4px Table 반환 높이와 최종 가시 기하의 차이를 독립 재현하는 것이다. 이어 실제 부분 저장 프레임과 합쳐진 셀의 조각 경계를 검증한다. 별도 앞 문단 사례를 준비하는 과정에서 splitParagraph가 표 앵커의 텍스트 순서를 바꾸는 조건도 발견했으므로 원본 앵커 순서 보존을 독립적으로 재현한다.
