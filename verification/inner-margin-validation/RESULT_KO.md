# 빈 안쪽 여백 입력의 원자적 거절

기준 b532789a505c9b8b9da15034f857a8b4a15ed2bf에서 실제 Mac Electron 44.3.0으로 재현했다. 셀 안 여백 지정이 활성인 상태에서 왼쪽 값을 지우고 확인하면 엔진 속성은 그대로인데 창이 닫히고 undo 0→1, dirty false→true가 됐다. 표 안쪽 여백은 엔진에서 거절됐지만 입력 오류 안내가 없었다. HWP/HWPX 두 입력 형식에서 동일했다.

활성 셀 안쪽 여백과 모든 표 안쪽 여백을 명령 실행 전에 정수·signed i16 범위로 검증한다. 빈 값은 명시적으로 거절하고 오류 입력의 탭을 열어 메시지와 포커스를 표시한다. 비활성 셀 여백은 적용하지 않는다. 기존 정밀 HWPUNIT 보존 동작을 유지한다.

최종 실제 Electron 36개 경우: 양형식 × 셀/표 × 4방향 × 빈 값 단독/너비와 혼합 32개, 양형식 × 너비 단독/너비·높이 동시 4개. 첫 거절 직후 전체 문서·양형식 export SHA·undo/redo 스택·dirty 불변을 직접 확인했다. 반복 거절 직후 직접 검사는 undo/redo 스택·dirty 불변이다. 다른 탭에서 확인해도 오류 필드가 표시된다. 유효 1.7mm 재입력은 482 HWPUNIT으로 적용됐고, 혼합 너비 31mm도 한 명령으로 적용됐다. 너비만 편집할 때 원래 높이 정밀값을 보존했다.

36 undo/redo 쌍과 HWP/HWPX 실제 호스트 저장·재열기 72회를 통과했다. 재열기 뒤 전체 SVG, 페이지 수, 본문, 모든 셀 문단/문자 스타일 ID, 표 속성과 스타일 목록이 일치했다. 실제 저장 바이트 SHA는 현재 export와 일치했고, 독립 Native 재읽기 72개도 전체 SVG·속성·텍스트 일치를 통과했다. renderer 오류 0, 정상 종료 0. TypeScript 검사와 git diff --check 통과. 기존 WASM SHA 14c6978c7712faf84846c65619adc137bd923b17c3d47fd715544dc76fd1ec99를 재사용했다.

로컬 증거는 ../inner-margin-validation-qa/baseline, final, native-final에 보존하고 proof.json에 해시를 기록했다. 원본·이전 QA·beta.2는 보존했다. QA는 전용 프로필과 기존 Mac Electron을 사용하며 선택/읽기만 기존 핸들로 보조하고 편집·이력·저장·재열기는 제품 경로를 사용했다. OS 파일 선택창, 물리 IME, 수동 GUI, Linux, 한컴 교차검증은 하지 않았다. 패키징·병합·릴리스는 수행하지 않았다.
