# Namespace context of preserved header fragments

On main `3a9c10de44b310257c3cb2f044ea81346b07c482`, a valid header can bind
`ns0` on `hh:head`, `hh:numberings`, or `hh:numbering`, then use
`ns0:paraHead`. The parser retains the raw children while discarding that parent
binding. The serializer creates a header with its standard namespace declarations
and splices those children into it. Saving therefore emits an undeclared prefix.
A default namespace can disappear without a syntax error, changing the expanded
name of `paraHead` instead. These violate namespace meaning, rather than being a
limitation of the namespace-aware QA oracle. See the [W3C namespace scoping and
defaulting rules](https://www.w3.org/TR/REC-xml-names/#scoping).

The old PR93 regression documents already contain an unbound `ns0` prefix in their
inputs; those records alone do not prove that the last save introduced it. The new
reproduction starts from a synthetic blank document and supplies valid bindings.
No user document or historical evidence was repaired or replaced.

The correction captures in-scope bindings for numbering/bullet fragments in one
header pass. Bindings that differ from the regenerated header environment are
attached to each top-level raw child unless that child already declares them.
Local shadows and `xmlns=""` take precedence. Existing bytes, QName-valued
attributes, format strings, levels 8–10 and zero/sentinel attributes are retained.
The parser and writer share their canonical header environment, so ordinary
fragments retain their previous output. No namespace URI is guessed for malformed
input. This is scoped to numbering/bullet raw fragments; other header raw-splice
families and general malformed-input repair are outside this patch.

The synthetic seed contains `본문 한글😀`; it was generated by `createEmpty`,
`createBlankDocument`, and `insertText`, then exported through the current-main
SDK. Fixtures change only copies of that seed's header and keep ZIP compression
methods. Cases cover root/collection/item inheritance, default namespaces,
parent/child and standard-prefix shadows, sibling scopes, escaped URI and QName
attribute values, bullets, and an actual numbered body paragraph. One undeclared
input is an explicit negative control.

```sh

cargo run --offline --locked --manifest-path engine/Cargo.toml --example header_namespace_check -- /absolute/fresh-fixtures/manifest.json /absolute/fresh-native
python3 scripts/check-header-namespace-xml.py fixed /absolute/fresh-fixtures/manifest.json /absolute/fresh-native /absolute/native-xml.json
node scripts/build-wasm-release.mjs /absolute/fresh-sdk/pkg
node scripts/check-header-namespace.mjs /absolute/fresh-sdk/pkg /absolute/fresh-fixtures/manifest.json /absolute/fresh-sdk-check
python3 scripts/check-header-namespace-xml.py fixed /absolute/fresh-fixtures/manifest.json /absolute/fresh-sdk-check /absolute/sdk-xml.json
```

The XML oracle compares expanded element/attribute names and exact raw-subtree
text/children. It checks six exports per fixture and exact per-case filenames;
a shorter case name must not also match a longer case name. Public SDK checks
include insertion, snapshot undo/redo, cold reopening and two additional save
cycles. They compare numbering/source/render state against current main. Native
checks compare the complete numbering-head model and source across six reopen
cycles. Neither check certifies HWPX schema validity, actual app behavior, physical
IME or editable Hancom interoperability.

On the supplied macOS, `xmllint --noout` emits namespace errors for the broken main
save but returns exit 0. Its exit status alone is therefore not a namespace-validity
gate. The Python expanded-name oracle detects both unbound prefixes and silent
default-namespace loss. Diagnostic stderr and original failed harness phases are
retained separately, rather than being reported as product passes.

## Author verification on the candidate SDK

The final 15 cases include 14 namespace-well-formed inputs and one undeclared-input
control. Main loses namespace meaning in 11 valid cases / 66 of 90 saved states;
the candidate has zero unexpected failures in 90 Native saves and 90 public-SDK
saves. All 168 outputs from valid inputs have well-formed XML. The 12 negative
control outputs remain malformed and are explicitly not repaired. Numbering/source
models and SDK render trees are unchanged against main; only the header member
changes in the 66 repaired SDK saves. Native/SDK header bytes match and remain
stable across repeated saves.

Existing 813 archive pairs remain byte-identical by ZIP member to main, including
the 140 old malformed legacy headers. The 2,376 equation-caret glyph probes,
99-position Native/default SDK checks, 23 adapted production input/history cases,
PR92 control tests, 35-document regression, two type checks and 110 host/Studio
unit tests pass again. Full Rust library/contracts compilation still stops on the
same four missing inputs; no whole-suite or CI success is claimed.

The candidate requires independent source review and actual-app QA on its exact
head/SDK before merge. The installed Hancom signature failure is retained as a
separate access/interop limit; no app launch, security bypass or setting change is
part of this task. Public release, notarization, deployment and cleanup are excluded.
