# 중첩 셀 사이의 입력·삭제 실행 취소 이력

현재 명령·SDK 경로에서, 같은 바깥 셀 안의 서로 다른 중첩 셀을 300 ms 이내에 편집하면 두 작업이 한 이력으로 묶인다. hit-test의 flat 좌표는 바깥 셀을 나타내는데 `InsertTextCommand`와 `DeleteTextCommand`의 병합 조건은 안쪽 경로를 비교하지 않았다.

정상 새 문서·표 생성, `copyControl`과 `pasteInternalInCellByPath`로 만든 재현 문서에서 첫 셀 `가나다🙂` 앞에 X, 두 번째 셀 `라마바𐐀`의 한 글자 뒤에 Y를 입력했다. 한 번 Undo하면 두 번째 입력만 사라져야 하지만, 첫 셀은 `나다🙂`가 되고 두 번째 셀의 Y는 남았다. 삭제도 서로 다른 셀의 글자가 한 셀로 복원됐고 잘못된 내용이 HWP/HWPX 저장·재열기에 남았다. 비정상 모델·XML을 주입한 입력이 아니다.

기존 섹션·문단·flat 셀·시간·연속 위치·글자 모양 조건을 유지하고, 셀 편집일 때 `cellAxisPath`의 깊이와 모든 control/cell/paragraph 항목이 같은지도 검사한다. 키 순서에 의존하지 않으며 flat 좌표와 동등한 1단계 경로는 계속 병합한다. 서로 다른 셀은 독립 Undo/Redo로, 같은 셀의 빠른 연속 편집은 기존 한 묶음으로 남는다. 저장 제어·검색 UI·엔진 형식·중첩 표 배치 및 필드 지원 범위는 변경하지 않는다.

## 검증

- 수정 전 새 단위 검사 43건 중 22건 통과·21건 실패, 수정 후 43건 통과. 중간·최내곽의 셀/컨트롤/문단, 깊이, 객체 키 순서, flat/1단계 동등성, 기존 시간·방향·서식 경계를 다룬다.
- 실제 SDK 30사례: 깊이 2·3, 서로 다른 최내곽/중간 셀 및 같은 셀 대조군, 삽입·Delete·Backspace와 ASCII/보조 평면 문자. 수정 전 18사례에서 78개 차이 관측이 있었으며 독립 결함 78건을 뜻하지 않는다. 수정 후 186상태·HWP/HWPX 저장/동일 프로세스 재열기 372회, 별도 새 프로세스 재열기 372회에서 모델 차이 0이었다. 다른 셀·원본 복사 표의 텍스트, 글자/문단 속성과 fields도 비교한다.
- 최종 strict 검사는 기존 main의 명령 소스를 넣으면 `undo-second` 모델 비교에서 실패한다. 기존 이모지 Undo 48건·SDK 32사례/512회 저장·재열기, Studio 타입, 기존 Studio 90건·호스트 20건도 통과했다.
- 재열기 실행기의 인자 누락으로 한 차례 검사가 중단됐다. 실패 기록을 보존하고 입력 경로를 보완해 남은 검사를 완료했으며 제품 실패나 통과로 계산하지 않았다.

WASM/엔진은 변경하지 않았고 기존 검증 SDK를 재사용했다. 프런트엔드와 Electron 소스 QA 실행본만 새로 준비했으며 배포·릴리스는 하지 않았다. 이번 실행기는 실제 GUI 제어 도구를 제공하지 않아 실제 앱 조작·화면/중첩 배치·한글 왕복은 미검증이다. GUI 재현은 셀을 이동하는 시간을 포함해 두 편집이 300 ms 안에 들어가야 하며, SDK 검사는 이를 명시한 타임스탬프로 통제한다. 물리 IME·전체 Rust·CI 성공을 주장하지 않는다. 독립 검토와 실제 앱 검증 전 병합하지 않는다.
