# Memo and settings header preservation

On main `03bc49ebb5e29df4fd1062523f4e9a3ee5eb07dc`, header memo/settings
extraction searches literal `hh:` boundary strings. Valid alias-prefixed elements
can be omitted; inherited bindings can be lost when fragments are relocated into
a regenerated header. A `>` inside a quoted attribute breaks the empty-element
heuristic. Comment text containing closing-tag strings can truncate/contaminate
the settings tail and produce files the engine cannot reopen.

The parser resolves element namespace URIs and locates actual direct children
using XML event boundaries, handles empty elements, and applies the existing PR94 namespace-completion helper with
the memo element's scope or the header scope for settings. Local declarations and
default namespace clearing retain precedence. No serializer, rendering, user-input,
endnote-layout or test-input recovery code is changed. No URI is inferred for an
undeclared input prefix.

The synthetic seed was generated by inserting a body comment into the committed
namespace test seed. It has no author or timestamp identity. The generator produces 32 cases with
31 namespace-well-formed inputs and one negative control; they cover aliases,
parent/local scope, Unicode, quoted delimiters, comment decoys, escaped URI/QName
values and absent metadata. Body-comment text/anchors and memo style/settings
records are checked. The dynamic `editRevision` cache token is recorded by the
engine but excluded from semantic content equality across edits.
