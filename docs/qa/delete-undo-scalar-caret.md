# 보조 평면 문자를 삭제한 뒤 실행 취소한 커서

현재 명령·SDK 경로에서 정상 새 문서 또는 표 셀에 `앞🙂뒤`가 있을 때 🙂 바로 뒤에서 Backspace를 누르고 실행 취소하면, 텍스트는 복원되지만 커서가 `뒤` 다음으로 이동한다. 이어 `X`를 입력하면 의도한 `앞🙂X뒤` 대신 `앞🙂뒤X`가 저장되고 재열기된다. SDK 검사에서 빠른 연속 삭제로 더 긴 보조 평면 문자 조합을 지운 경우 반환 위치가 문단 길이를 넘어 다음 입력이 거절되기도 한다. 실제 화면 동작과 구분한다.

`DeleteTextCommand.undo`는 삭제한 문자열을 올바르게 재삽입한 뒤, 커서 복원에만 JavaScript의 UTF-16 `length`를 사용했다. 본문·셀 SDK의 위치와 삭제 개수는 Unicode 스칼라 단위이다. 복원 위치에도 기존 `charCount`를 사용한다. 삭제 방향에 따른 기존 커서 규칙, 문자 삭제·필드 보호·이력 병합·저장 형식은 바꾸지 않는다. 결합 문자와 ZWJ를 한 글자 단위로 처리하도록 지원 범위를 넓히는 변경도 아니다.

## 재현 및 검사

```sh
node --test rhwp-studio/tests/delete-undo-scalar.test.mjs
node scripts/check-delete-undo-scalar.mjs fixed PKG FRESH_OUTPUT
```

Node 22.18 이상의 TypeScript 변환 기능으로 현재 제품의 명령·CommandHistory와 사용한 WasmBridge 메서드를 읽어 검사한다. 단위 검사는 실제 Undo/Redo 입력 라우팅도 사용하지만 DOM·화면·커서 렌더링은 포함하지 않는다. SDK 검사는 정상 공개 API로 만든 본문·셀 문서에서 실행하며 모델을 직접 바꾸거나 외부 문서를 추가하지 않는다.

- 수정 전 단위 검사: 48건 중 18건 통과, 30건 실패. 수정 후 48건 통과. 본문·셀·중첩 셀의 명령/입력 라우팅, Backspace·Delete, ASCII·한글·🙂·𐐀·결합 문자·ZWJ 및 연속 삭제의 병합을 다룬다. 중첩 셀은 단위 계약 검사이며 SDK·실제 화면 인증이 아니다.
- 수정 전 SDK 관측: 32개 사례 중 20개에서 문제를 관찰했다. 80개 관측 항목은 같은 사례의 커서·이어 입력·재실행 차이를 포함하므로 80개의 독립 결함을 뜻하지 않는다.
- 수정 후 실제 SDK: 본문·일반 셀 32개 사례, 256개 상태, HWP/HWPX 저장·동일 프로세스 재열기 512회, 차이 0. 별도 새 프로세스 재열기 512회와 Undo 상태 저장본에 이어 입력 128회도 통과했다. 마지막 strict 검사는 기존 main의 명령 소스를 넣으면 커서 불일치로 실패한다.
- 기존 Studio 검사 90건, 호스트 저장·이력 20건, Studio 타입 검사, 기존 혼합 필드 84개 및 일반 누름틀 28개 사례도 통과했다.
- 엔진 트리는 변경하지 않았고 검토된 기존 WASM을 그대로 사용했다. 새 Rust/WASM 빌드는 수행하지 않았다. 새 프런트엔드와 Electron 소스 QA 실행본은 준비했으나 이 작업의 실제 앱 조작·한글 왕복·물리 IME 검사는 미실행이다.

전체 Rust 검사와 CI 성공을 주장하지 않는다. 별도 독립 검토와 새 프런트엔드의 실제 앱 저장·재열기 검증 전 병합하지 않는다. 배포·릴리스·서명 설정 변경은 하지 않는다.
