# 네이티브 앱 메뉴 명령 뒤 포커스 후보

기준 main: `4c88173f82565b23cc61bc02d5934ce5561c227e`.

기존 네이티브 QA에서 앱 내부 편집 메뉴의 Undo와 Cmd+Shift+Z 후, 본문을 다시 클릭하기 전에는 Return/붙여넣기/한글 입력이 전달되지 않는 현상을 관찰했다. 이 관찰은 PR #110의 회귀로 판정된 것이 아니다. 현재 main과 해당 QA head `1997c665b7a5a794a04893a8a94d0b3c4816a688` 사이의 `desktop` 및 `rhwp-studio/src` 차이는 없다.

## 원인과 변경 범위

메뉴 제목은 마우스 기본 포커스 이동을 막지만, 항목은 일반 클릭으로 실행한다. 항목 mousedown의 기본 동작이 편집 textarea를 blur하고, click 후 메뉴를 닫아도 원래 입력란으로 돌아가는 경로가 없었다. 따라서 문서 편집 명령이 실행된 뒤 이어 입력할 수 있어야 한다는 계약과 어긋날 수 있다.

`ui/menu-bar.ts`만 수정한다. 기본 왼쪽 mousedown에서 메뉴 바깥의 기존 포커스를 기록하고, 같은 항목의 실제 포인터 click에서 명령 실행 직전에 복원한다. 이전 요소가 연결돼 있고, 현재 포커스가 body 또는 클릭한 명령 요소에 있을 때만 복원한다. 다른 곳으로 의도적으로 이동한 포커스와 키보드 활성화는 건드리지 않는다.

mousedown 기본 동작을 취소하지 않는다. 기존 blur/IME 조합 확정 흐름을 유지하기 위해서다. 명령 실행 뒤에는 포커스를 강제로 바꾸지 않으므로, 명령이 여는 대화상자의 포커스를 탈취하지 않는다. 검색·엔진·undo 구현·호스트 저장 코드는 수정하지 않는다.

## 완료한 검증

실제 MenuBar를 실행하되 DOM 이벤트와 기본 포커스 단계는 작은 adapter로 모델링한 회귀 검사다. 브라우저 실행이나 네이티브 실측으로 표시하지 않는다.

- 최종 회귀 14개: 원본에서 **9 pass / 5 fail**, 후보에서 **14 pass / 0 fail**.
- 포인터 Undo/Redo, 비활성 항목, 직접 메뉴 버튼, 키보드 click, 메뉴 제목/Escape, 바깥 입력란, 중간 포커스 변경, 분리된 이전 요소, blur 후 명령 실행 순서를 확인했다.
- Studio 기본 검사 **254 pass / 0 fail / 0 skip**. 타입 검사와 diff 공백 검사 통과.
- 독립 정적 검토에서 새 차단 결함은 발견하지 못했다. 실제 OS IME 이벤트 순서는 확인하지 않았다.
- 설치된 앱을 교체하지 않고, 일반 production 설정으로 Electron용 UI 자산만 전용 후보 경로에 준비했다. 관찰용 런타임 주입·디버그 노출·원격 디버깅은 없다. 앱은 실행하지 않았다.

SDK/WASM은 기존 것을 참조한다. SHA-256: `918c9c7dc584e4bdf28a8afa42fce062a077d944744d58bb4c37de74d559f697`. 엔진 재빌드, 의존성 설치·복제, 서명·보안 설정 변경, 배포 없음. PR #96의 외부 자료 권리 보류를 유지한다.

## 네이티브 QA 대기 — 병합 전 필수

동일 Mac에서 다른 QA가 입력을 소유하고 있어 화면·마우스·키보드 조작을 중단했다. **이 후보의 실제 네이티브 수정 전후 효과는 아직 미검증**이며, 아래 비교를 마치기 전 병합하지 않는다. 물리 키보드 검증과 OS 자동화 결과는 구분한다.

1. baseline과 candidate를 순차적으로 별도 프로필에서 실행한다. 사용자 문서 없이 합성 새 문서를 사용한다.
2. 본문에 합성 텍스트를 입력·확정한다. 앱 내부 편집 메뉴 > Undo, 메뉴 > Redo 및 Cmd+Shift+Z를 각각 사용한 직후 본문 재클릭 없이 Return/붙여넣기/한글 이어 입력을 확인한다. AX 포커스, 화면, 저장한 사본 본문으로 전후를 비교한다.
3. 한글 조합 중 메뉴 Undo를 선택해 조합이 한 번만 확정되고 정확히 한 번 되돌려지는지, Redo 및 이어 입력에서 중복·누락이 없는지 확인한다.
4. 명령이 여는 비검색 대화상자(예: 글자 모양)의 입력 포커스가 유지되는지 확인한다. 취소 후 기존 문서 보존도 확인한다.
5. 비활성 Undo 클릭, 메뉴 열기→Escape, 바깥 서식 입력란 클릭, 직접 메뉴 버튼, 키보드 활성화를 확인한다. 바깥 입력란의 의도한 포커스를 빼앗지 않아야 한다.

재현되지 않거나 다른 원인이 확인되면 후보를 수정/보류한다. baseline의 기존 관찰만으로 수정 효과를 확정하지 않는다. 전체 앱·전체 E2E·물리 IME·전체 Rust·CI는 검증하지 않았다.
